# Home Reps: notes for Claude

- This web app is the prototype of a native app (React Native + Expo, iOS and Android, English UI). Plans and decisions live in `docs/` (start with `docs/fase-1-arquitectura.md`); team docs are in Spanish.
- Single-file app: `index.html` holds all CSS, HTML and JS. Keep it dependency-free with no build step, so it runs from GitHub Pages and by opening the file. The one exception: MediaPipe pose is lazy-loaded from jsDelivr only when camera counting starts, and the app falls back to tap counting without it.
- Data tables live near the top of the script: `EX_RAW` (exercises: id, name, muscle groups, equipment, level 1-3, dose, unit, steps), `STRETCH_RAW`, `MEALS`, `RECIPES` (Recipes tab; videos live in `media/` as .mp4 + .webm with a .jpg poster), `PLAN` (weekday split) and `GROUPS`.
- Muscle shapes are SVG paths in `FRONT_PATHS` / `BACK_PATHS` (viewBox 200x430). Paths marked `1` are mirrored to the other side.
- Colors are CSS variables on `:root` with dark-mode overrides; use the tokens, not literal colors.
- State is saved in `localStorage` under the `homereps.` prefix (profile, schedule, done, tab, mode, onboarding, health, plan, points, challenges, habits, alarm, alarmState, meals, log, session, bestStreak, game, rivals, master, masterReq, hints, hintsOff; `survey` and `whyAsked`; `survey` is legacy and no longer read, and `points` is only read once to seed `game`). Keep old keys readable when changing data shapes.
- Plan safety rules live in the `safety-core` block of `index.html` (pure functions, no DOM). Every plan draft, AI or local, must pass `validatePlan`. Run `node --test tests/*.test.mjs` after touching that block.
- Every open starts on the Challenge/Training picker. Challenge asks nothing (high-impact challenges need the `safety` flow, which asks age if missing). Training's first use runs the 5-screen `gym` flow (age, goal, experience/days/minutes, time and sleep, safety) that builds a starter week shown as a 4-week block in the Plan tab (`v-sched`). The daily battery (sleep first, shown on Today and at the top of the Challenge hub; a red battery pre-selects the easier challenge version) and block week live in the `habits-core` block (pure functions, tested in `tests/habits.test.mjs`); see `docs/plan-y-habitos.md`. Exercises with gym equipment only show for `track: 'gym'` users.
- The app has two modes picked on every open: Training (the tabs) and Challenge (`v-challenge` hub plus the full-screen `#arena`). Challenge catalog and progression rules live in the `challenge-core` block (pure functions, tested in `tests/challenges.test.mjs`); see `docs/retos-y-onboarding-corto.md`.
- Phase 3: camera rep counting rules live in `pose-core` and wake-up alarm rules in `alarm-core` (pure functions, tests in `tests/pose.test.mjs` and `tests/alarm.test.mjs`); see `docs/fase-3-alarma-camara.md`. Camera frames never leave the device; meal photos go to Claude only with the separate tick box.
- Duels (challenge a friend) use the published page's shared `db` (`duels` collection: challengeId, scaled, createdAt, from/to {uid, score, medal, video asset id, at}, status) plus `assets` for attempt videos and `user` for ids and names. Store only user ids, never names. Nothing is shared without the tick box; videos are recorded with MediaRecorder or added from the gallery and shrunk on the device to under 20 MB. Without these capabilities (GitHub Pages, local file) the Duels section is hidden. See `docs/duelos.md`.
- Live workout logging (`#session` overlay: sets, previous, suggestion, PRs, rest timer, plates, warm-up), the Progress tab (streak heatmap, strength, volume and battery charts), the Body recovery map and the streak chip use the `training-core` block (pure functions, tests in `tests/training.test.mjs`). Tabs are Today, Plan, Body, Progress, Food; Recipes opens from Food. See `docs/comparativa-mercado.md`.
- Every exercise and challenge move has a looping SVG animation: the rig (2-bone IK, pose blending, timing) is the `anim-core` block (pure, tested in `tests/anim.test.mjs`); poses live in `ANIMS` (one entry per `EX_RAW` id, side view unless `v:'front'`), drawn by `animScene` and mounted automatically for any `svg[data-anim]` (use `animSvg(id)`). The first two muscle groups glow. They show in How to (steps folded away), exercise cards, Today, the workout, challenge intros and the alarm. Add an `ANIMS` entry when you add an exercise.
- XP, levels and points: every reward goes through `gameEvent()`, which applies the `game-core` rules (`GAME` holds every number: XP per activity, daily caps, level curve, points per level, anti-cheat limits; tests in `tests/game.test.mjs`). Never add XP or points any other way. The `game` key holds the XP ledger and the append-only points ledger. Challenge XP feeds the same level. After changing `game-core`, run `node scripts/sync-game-core.mjs` so the Supabase functions use the same rules.
- Rankings by sector (gym, calisthenics, home bodyweight) and private leagues use the shared `db` (`players/<uid>` with nickname, sector, XP and league codes; `leagues/<code>`). Only nicknames are shown, never account names. Someone in your leagues passing you triggers a notice every time. Tips and A/B challenges are `LEARN_DEFAULT` plus rows in the `content` collection (A/B options can use `ANIMS` ids such as `pushup-sag`, `squat-half`, `plank-pike`).
- The MÁSTER section (coach Dani's personal plans) is a secret: nothing in the app may hint at it. Its unlock and texts live only in the `master-core` block; how it unlocks is documented in `dev/master-privado.md` only (never in README or docs). Visible text says "a coach", not Dani's name.
- Backend: `supabase/` (migration with row level security, `seed.sql`, `submit-event` and `delete-account` functions). The client never writes XP, points or flags; `submit-event` validates events with `_shared/submit.mjs` + `_shared/game-core.mjs` (tests in `tests/submit.test.mjs`). Check the database rules with `scripts/test-supabase.sh`.
- Visual first: every section has an icon (`ICONS`, drawn with `ico()` / `tile()`), a one-line hint the first time it's opened (`hintText`, personalised by level, track and plan; shown by `placeHint()`), shortcut tiles on Today and the Challenge hub (`quickTiles`), and a Help center (the ? in the header; `HELP` topics with steps and a button that jumps there via `jumpTo`). When you add a section, add its icon, hint and Help topic. Never mention the MÁSTER in hints or Help.
- Motion uses the `--spring` / `--out` easing tokens; JS checks `RM()` and CSS has a reduced-motion rule, so keep both working when adding animation.
- Test changes at phone width (about 400px) in light and dark mode.
